# 基本設計書

要件定義書をもとにした第1週時点の設計案。実際の構成・実装は授業中に確認し、進み具合に応じて見直す。

## 1. 画面設計

### トップページ（PC）

- 表示するもの：アプリ名、今日の日付、全体評価（大きく表示）、日別平均の折れ線と集計対象投稿数の棒グラフ、マイスレッド一覧、選択中スレッドの今日の投稿。
- 投稿には時刻の下にスレッド名を表示する。投稿内容は選択中スレッドの範囲で見る。
- マイスレッドの名前は左寄せ、設定アイコンは右寄せ。星集計OFFは星に×、1時間後削除ONは目に×のアイコンを表示する。
- 画面上のボタン・リンク：スレッド選択、スレッド作成、記録追加、設定。
- グラフ：折れ線は日別平均、棒は集計対象投稿数。評価がない日は線の値を0にせず空欄にする。

### トップページ（スマートフォン）

- 縦一列の簡易表示。全体評価・直近グラフ・スレッド一覧を上から表示し、今日の投稿一覧は選択したスレッドのページで確認する。
- 画面幅が小さいためPC版の全情報を一画面に詰め込まず、全体評価／スレッド／投稿の画面に分ける。
- 色・設定アイコン・スレッド内で投稿を見るルールはPC版と共通。

### 投稿・登録フォーム

- 入力する項目：文章（必須）、星評価1〜5（星集計ONのスレッドでは必須、OFFでは表示・入力不要）、画像（任意、最大4枚）。投稿日時・日付は記録時に保存する。
- 画像はJPG/JPEGまたはPNG、1枚5MB以下。形式・容量を超えたら保存せず、理由を表示する。
- ボタン：投稿、キャンセルしてスレッド表示に戻る。

### スレッド作成・設定

- 入力する項目：スレッド名、星評価を集計するか、1時間後削除を有効にするか。
- 初期設定は星集計ON・1時間後削除OFF。1時間後削除ONなら星集計OFFに固定する。
- 初期スレッド「一日の評価」は常に存在し削除不可。これがある場合に限り、特殊設定のスレッドを作成可能。
- 星集計OFFには星×、1時間後削除ONには目×のアイコンを表示する。

### 編集画面

- 入力する項目：投稿本文、スレッド設定に応じて星評価、任意の画像。
- ボタン：保存、削除、キャンセル。
- 削除期限を過ぎた1時間後削除投稿は再表示・編集できない想定。詳細な操作仕様は実装時に確認する。

### 第5週の個人拡張で追加・変更する画面（予定）

- 追加・変更する画面：スレッド設定と投稿の期限削除処理。
- 表示したいもの：スレッド名と「1時間後削除」設定。スレッド名の右側に目×アイコン。
- 操作できること：設定をONにすると星集計をOFFにし、投稿を1時間後に削除。サーバー停止中に期限を過ぎたものは次回起動時に削除する。
- 最初に作る最小版は、期限を保存し、期限切れを削除できるところまで。授業の進行に応じて範囲を見直す。

## 2. データ設計

以下はJSONの形の案。日別平均・全体評価・グラフ用件数は投稿から計算する想定で、二重保存を避ける。画像本体はファイル、JSONにはファイル名を保存する。

```json
{
  "threads": [
    {
      "id": "thread-1",
      "name": "一日の評価",
      "aggregate_rating": true,
      "delete_after_one_hour": false
    },
    {
      "id": "thread-2",
      "name": "気持ちの整理",
      "aggregate_rating": false,
      "delete_after_one_hour": true
    }
  ],
  "posts": [
    {
      "id": "post-1",
      "thread_id": "thread-1",
      "created_at": "2026-09-25T10:15:00+09:00",
      "date": "2026-09-25",
      "text": "今日は人の手伝いができた。",
      "rating": 5,
      "image_files": [],
      "delete_at": null
    }
  ],
  "settings": {
    "email_reminder_enabled": true,
    "email_reminder_mode": "every_night",
    "email_address": ""
  }
}
```

- 1時間後削除の投稿は、作成時刻から計算した期限までに本文・画像・星データを削除する。停止中に期限が過ぎた場合は、次回起動時に期限切れを処理する。
- 画像保存フォルダの場所、JSONファイル名、SMTP設定の保存方法は未決定。メールアドレス等の個人情報・秘密情報をソースコードに直接書かない。
- 日付の切替基準はPCのローカル日付を使う想定。実装前に確認する。

## 3. 画面遷移

- トップページ → スレッド選択 → 選択スレッドの投稿一覧
- トップページまたはスレッド一覧 → スレッド作成 → 作成したスレッドの投稿一覧
- スレッドの投稿一覧 → 投稿フォーム → 投稿一覧
- 投稿一覧 → 投稿編集 → 保存または削除 → 投稿一覧
- スマートフォン：全体評価・グラフ → スレッド一覧 → スレッドの投稿一覧 → 投稿フォーム

文章・画像・投稿一覧は所属スレッド内で完結させる。スレッドをまたいで表示するのは、星評価の集計とグラフ用投稿数のみ。

## 4. 使用する技術

- 言語・フレームワーク：Python / Flask / Jinja2
- データ保存：JSON。画像を実装する場合は画像ファイルを別に保存し、JSONにはファイル名を記録。
- バージョン管理：Git
- 第5週で追加する技術（予定）：未定。メール通知でSMTP等が必要になる場合は、授業で扱えるか確認してから判断する。

## 5. 実装順

- 第2週：Flaskの起動、PC・スマートフォン向けトップページ、スレッドと投稿の表示。
- 第3週：文章・星評価の入力、JSONへの保存と読み出し。画像の追加は授業の進行を見て判断。
- 第4週：編集・削除、動作確認、Gitへの記録。データ構造と集計の理解を確認。
- 第5週：第一候補の1時間後削除を最小版から実装。画像投稿・22時メール通知は進み具合で再検討。
- 第6週：仕上げ、発表準備、動作確認、Git記録、振り返り。
